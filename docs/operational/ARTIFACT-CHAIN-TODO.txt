Feature docs trong repo (hotel, chain, common/*.spec.yaml, generated/) =
  CHUỘT BẠCH thử nghiệm artifact chain. Base đang xây — KHÔNG giữ tương thích
  ngược path/layout cũ. Sai thì đập, xóa, replace; cản trở thì delete.

App code (pages, components, services, …) = base kỹ thuật đã xong;
  chỉ sửa khi user yêu cầu feature/app — mặc định session tối ưu AI layer.

AI infra (skills, extracts, rules .cursor/) =
  refactor có chủ đích — cập nhật skill/extract trong cùng PR với đổi path;
  không cần symlink/re-export flat paths lâu nếu gây rối.

Legacy code bên ngoài repo (mairy-backend, …) =
  không xóa — chỉ đọc 1 lần vào trace. Khác với feature docs trong portal.

## 1.1 Bundle schema (SSOT authoring)
[ ] schema: portal-feature-bundle/v1
[ ] Top-level: id, title, specOrigin, spec, legacy, design, review, openQuestions, _meta
[ ] specOrigin: legacy | requirement
[ ] grillStatus: bqaFacts, bqaOpen, dev, full
[ ] spec section — design v1 only (chưa gen-ready):
      [ ] actors, entities, relationships, requirements
      [ ] ui.routes, ui screens hoặc design.zones (structured)
      [ ] api query/response
      [ ] acceptance
      [ ] KHÔNG codegen, ui.filters, ui.columns, tags gen
[ ] legacy section — legacyEvidence first-class:
      [ ] behaviors[]: id, fact, source[], confidence
      [ ] fields[]: name, source[], confidence
      [ ] ui[]: pattern, source[]
      [ ] evidence: [{ file, symbol, lines }] — pointer only
      [ ] refs: { "legacy://...": { file, symbol, summary[] } }
      [ ] legacyRef → trace#slice khi module đã có _legacy.trace.yaml
[ ] design section — normalized portal intent:
      [ ] inherits: admin-crud (optional)
      [ ] shell, patterns, zones[], components[role+tag+label+hint]
      [ ] behavior: create/update/delete verb blocks
      [ ] tokens (optional), deviations (#legacy-global-ui-violation)
[ ] review section — CHỈ prose cho BA (không split sang ir):
      [ ] summary, layoutNotes
[ ] origin / confidence per section (optional)
